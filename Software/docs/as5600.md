# AS5600 angle sensors

An AS5600 is a magnetic angle sensor: a chip under a small magnet on a turning shaft. Given the angle range it should cover, a sensor set for, say, 35° of collective travel uses the **whole** of its reading for those 35°, instead of the tenth of it that 35° is out of a full turn. The two HeliSR boards set that range differently:

- **[Rev 3.0](#rev-30-programming-with-the-prog-buttons)** reads the sensor's analog output on AX1–AX4. Its **PROG1** and **PROG4** buttons burn the range into the chip, **once**.
- **[Rev 4.0](#rev-40-setting-the-range-over-i2c)** reads the sensor over I²C on any AX port. The board keeps the range and writes it to the sensor every time it starts: nothing is burnt, and it can be set again at any time.

The modules are prepared differently for each board, so read the section for yours.

## Rev 3.0: programming with the PROG buttons

**The range can be programmed only once per chip.** Read this section first.

### How the programming works

The chip has a programming mode that needs no I²C (the HeliSR's I²C pins drive its shift registers): the datasheet calls it OUT-pin programming, "Option B". While the chip's PGO pin is held low and the chip isn't programmed yet, it holds its OUT pin high and waits. Pulling OUT to GND for at least 100 ms stores the current angle. The first pull stores the **start** angle, the second the **stop** angle; then the chip burns both, permanently, and OUT becomes an analog output covering start to stop.

PROG1 pulls AX1's signal line (the sensor's OUT) to GND through 1 kΩ while it's held; PROG4 does the same for AX4. On a pot or a Hall sensor the buttons are harmless: pressing one just pulls the reading down.

### Preparing the module

For the common WWZMDiB AS5600 module (23 × 23 mm, Amazon B0CM3C8KFT), running on the Pro Micro's 5 V:

- **Keep R4**, the 1 kΩ from PGO (labelled GPO on the module) to GND. PGO low is what enables the programming. Some reviews say to remove it "for analog output": that gives the factory full-circle range instead, which can't be changed without I²C.
- **Remove R1**, the 0 Ω link between VDD5V and VDD3V3. It puts 5 V on the chip's 3.3 V pin (absolute maximum 4.0 V). Without it, the chip's own regulator feeds that pin.
- **Wire DIR** to GND or VCC; it floats on this module. DIR sets which way the reading rises: **GND = clockwise, VCC = counterclockwise**, seen from the chip's top face. Programming must turn the magnet in that direction, from start to stop.
- **Magnet:** a diametrically magnetised disc (5 × 2 mm is typical), centred over the chip, about 0.5–3 mm above it.

### Wiring

Connect the module's **VCC, OUT and GND** to **AX1 (J11)** or **AX4 (J14)**: pin 1 VCC, pin 2 signal, pin 3 GND. Only those two inputs have PROG buttons. Don't put a capacitor on the signal line.

### Programming with HeliSR Configurator

The **Board** page has an **AS5600 programming helper**. It can't press the button for you, but it watches the live reading, so it sees each press and checks the result.

1. Assemble the mechanism with the sensor in place, plug the board into USB and open the **Board** page.
2. Pick the input, **AX1 (PROG1)** or **AX4 (PROG4)**, and click **Start**. An unprogrammed sensor reads near the top (about 4092) wherever it is; the helper checks that. If it doesn't, the helper warns you: the chip may be programmed already, or R4 has been removed.
3. Move the control to its **start** position: the end the reading should start from, given DIR. Hold **PROG1** (or PROG4) for about a second and let go. The helper shows the press, and warns if it was shorter than the chip's 100 ms.
4. Move to the **stop** position, at least 18° away, in the DIR direction. Hold the PROG button again for about a second and let go. The chip burns both angles.
5. Move the control through its whole range. The helper says **Programmed** when the reading follows it, and shows the lowest and highest readings it has seen. If the reading stays at 0 wherever the sensor is, the burn failed (the chip signals that by holding OUT low).
6. Sweep the whole range once more, then click **Use the measured range as the calibration**. It sets the calibration of every axis that uses that input (choose the input as an axis source on the Axes Config page first). Then **Write config to Device**.

#### Examples from the UH-1 collective

- **Collective, in the MkIII base, on AX1:** DIR to **VCC**. Start: collective fully **down**. Stop: fully **up**.
- **Throttle, in the Huey head (Rev 4), on AX4:** DIR to **GND**. Start: the grip at the **idle** stop. Stop: **full open**. Afterwards the throttle reads 0 at the idle stop and full scale at full open; set the sim's idle point a little above 0.

### Troubleshooting

| What you see | Why, and what to do |
|---|---|
| The reading sits near the top wherever the sensor is | Not programmed yet: program it |
| The reading changes only a little over the whole travel, and PROG does nothing | PGO isn't low: R4 was removed or the module has none. Wire GPO to GND, power it again, and program it |
| The reading is 0 wherever the sensor is | The burn failed, or a PROG button is stuck. A failed chip needs reprogramming over I²C or replacing |
| The axis works but rises the wrong way | Tick **Inverted** on the Axes Config page |
| The range covers almost a full turn instead of your travel | The stop was set by turning against the DIR direction. The chip can't be reprogrammed: replace it, or reprogram it over I²C |
| Jumpy readings | Check the magnet is centred and close enough. Use the axis Filter (Axes Config, extended settings) |

**Reprogramming** needs I²C, which Rev 3.0 can't do: an Arduino on the module's SDA/SCL pins with the module unplugged from the board, or a fresh module.

## Rev 4.0: setting the range over I2C

> **Not tried on hardware yet.** No Rev 4.0 board has been built. The firmware's sensor code is tested on the PC against a model of the board's I²C switch and the AS5600 (see [Development](development.md#testing)), but not against real chips and cables.

Rev 4.0 has a **PCA9546A I²C switch**: every AS5600 has the same address, so each AX port has its own channel, and the firmware reads one port at a time. It reads each sensor's **ANGLE** register, which runs 0–4095 across the range set, and scales it to the same 0–4092 as an analog input. The start and stop are written to the chip's working registers (ZPOS and MPOS) every time the board starts, from settings the board keeps in its EEPROM. With them, the chip's settings register (CONF) is set to its factory state: full power, the standard filtering, no watchdog. So a module that someone has configured differently, even burnt, still reads the same. **Nothing is ever burnt into the chip**, so the range can be set as often as you like. There are no PROG buttons.

### Preparing the module

For the common WWZMDiB module, on the Pro Micro's 5 V (the board README's [AS5600 modules](../../PCB/HeliSR_Rev4.0/README.md#as5600-modules) has the details):

- **Remove R1**, the 0 Ω link between VDD5V and VDD3V3, as for Rev 3.0.
- **Remove R4**, the 1 kΩ from PGO (GPO) to GND, unlike Rev 3.0: PGO low selects OUT-pin programming, where two 100 ms shorts of OUT to GND burn a range into the chip for good. Leave OUT unconnected.
- **Wire DIR** to GND or VCC. It still sets which way the angle rises (GND = clockwise, seen from the chip's top face). If the angle falls from your start to your stop, the helper notices and sets the range the other way round (below).
- **Check the module's pull-ups** on SDA and SCL, with a meter, as the board README describes: none, 10 kΩ or 4.7 kΩ is fine; under 2 kΩ is too strong with the board's own 2.2 kΩ, so remove them. Remove them too if they go to the chip's 3.3 V pin rather than VCC.
- **Check for about 1 µF from VDD3V3 to GND** once R1 is off: on 5 V that pin is the chip's internal regulator output, which needs it. Add a 1 µF ceramic if the module has less.
- **Magnet:** as for Rev 3.0, a diametrically magnetised disc centred over the chip, about 0.5–3 mm above it.

### Wiring

Any of **AX1–AX4 (J11–J14)**: pin 1 **SDA**, 2 **GND**, 3 **VCC** (5 V), 4 **SCL**. This is not the Qwiic / STEMMA QT order, on purpose: those boards are 3.3 V. On a long cable, twist SDA with GND and SCL with VCC.

### Setting the start and stop

The **Board** page shows the Rev 4.0 board when one is connected. Each AX row says its sensor's state, and on the right is the **AS5600 sensors (I²C)** helper.

1. Assemble the mechanism with the sensor in place and plug the board into USB.
2. In the helper, pick the port. **State** should say **OK**, the **AGC** should be somewhere in the middle (it sits at an end when the magnet is too close or too far), and the **Raw angle** should follow the control.
3. Move the control to the end where the reading should start, and click **Set start**.
4. Move it to the other end, at least 18° away, and click **Set stop**. The helper follows the raw angle in between, so it knows which way you went and how far. The board saves the range at once, writes it to the sensor, and the state adds **range set on the sensor**.
5. The **Output** bar now runs from 0 at the start to 4095 at the stop. That's what the axis gets.
   - If the angle falls from your start to your stop (DIR is the other way), the helper sets the range the other way round and says so: the output then runs from 4095 at your start to 0 at your stop. Tick **Inverted** on the axes using that port, or wire DIR to the other side and set the range again.
6. Click **Use the sensor's whole output as the calibration** to set the calibration of every axis that uses that port to the full range (choose the port as an axis source on the Axes Config page first). Then **Write config to Device**.

**Whole circle** clears the range: the sensor reads 0–4095 over a full turn again. For a 360° control, set the wrap point with the axis's **Offset** instead.

The start and stop belong to the board, not to a profile: writing a profile, resetting the settings or updating the firmware leaves them alone. The helper saves them as soon as you click; there's no need to write the config for them.

### The I²C clock

**100 kHz** is the default and suits most cables. If a port with a long cable shows errors, choose **50 kHz** or **25 kHz** in the helper (10 kHz is there as a last resort). The board saves it at once. The firmware reads one port per pass, so a slower clock makes each pass longer: by about 1.7 ms at 100 kHz, 7 ms at 25 kHz and 17 ms at 10 kHz (calculated from the transfers, not measured). At 10 kHz the buttons and the USB reports slow down to match.

### Examples from the UH-1 collective

With DIR wired as for Rev 3.0, the same start and stop positions give the same result:
- **Collective, in the MkIII base, on AX1:** DIR to **VCC**. Set start with the collective fully **down**, set stop fully **up**.
- **Throttle, in the Huey head, on AX4:** DIR to **GND**. Set start at the **idle** stop, set stop at **full open**.

### Troubleshooting

| The state says | Why, and what to do |
|---|---|
| no sensor | Nothing answers on that port: check the cable, its pin order (SDA, GND, VCC, SCL) and the module's power. A sensor plugged in later gets its range as soon as it answers |
| no magnet / magnet too weak or too far | Move the magnet closer and centre it over the chip |
| magnet too strong or too close | Move it further away |
| the board's I²C switch doesn't answer | Every port says so: the PCA9546A or its pull-ups (R9–R11) aren't working. On a bare Pro Micro with Rev 4.0 firmware this is normal |
| bus stuck: check this port's cable | Something on that port held a line low. The firmware resets the switch, leaves the port alone for a moment and carries on with the others. Check the cable for a short, and try a slower clock |
| errors keep counting on a long cable | Try a slower I²C clock, and check the pull-ups (the board README's [AS5600 modules](../../PCB/HeliSR_Rev4.0/README.md#as5600-modules)) |
| range not set on the sensor yet | The board couldn't write the start and stop, or the chip didn't keep them; it tries again every few visits |

A chip already programmed on Rev 3.0 (with the PROG buttons) may work on Rev 4.0 once R4 is removed: the board writes its own start and stop over the burnt ones every time it starts. Whether a burnt chip keeps them hasn't been tried; if it doesn't, its state says "range not set on the sensor yet".
