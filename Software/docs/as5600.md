# AS5600 angle sensors

An AS5600 is a magnetic angle sensor: a chip under a small magnet on a turning shaft. Given the angle range it should cover, a sensor set for, say, 35° of collective travel uses the **whole** of its reading for those 35°, instead of the tenth of it that 35° is out of a full turn. The HeliSR Rev 4.0 board reads the sensor over I²C on any AX port. The board keeps the range and writes it to the sensor every time it starts: nothing is burnt into the chip, and the range can be set again at any time.

> **Not tried on hardware yet.** No Rev 4.0 board has been built. The firmware's sensor code is tested on the PC against a model of the board's I²C switch and the AS5600 (see [Development](development.md#testing)), but not against real chips and cables.

The board has a **PCA9546A I²C switch**: every AS5600 has the same address, so each AX port has its own channel, and the firmware reads one port at a time. It reads each sensor's **ANGLE** register, which runs 0–4095 across the range set, and scales it to the same 0–4092 as an analog input. The start and stop are written to the chip's working registers (ZPOS and MPOS) every time the board starts, from settings the board keeps in its EEPROM. With them, the chip's settings register (CONF) is set to its factory state: full power, the standard filtering, no watchdog. So a chip that someone has configured differently, even burnt, still reads the same. **Nothing is ever burnt into the chip**, so the range can be set as often as you like.

## The sensor board

Use the AS5600 sensor board, [`PCB/AS5600`](../../PCB/AS5600/README.md). It's wired for the Pro Micro's 5 V as the datasheet asks, with no pull-ups of its own (the board's ports have them), PGO and OUT left open so nothing can be burnt into the chip, and **DIR tied to GND**: the angle rises clockwise, seen from the chip's face. If the angle falls from your start to your stop, the helper notices and sets the range the other way round (below).

**Magnet:** a 6 × 2.5 mm diametrically magnetised disc (Radial Magnets 9049), centred over the chip, 1.0 mm above it in both the base and the head (the datasheet allows 0.5–3 mm).

## Wiring

Any of **AX1–AX4 (J11–J14)**: pin 1 **SDA**, 2 **GND**, 3 **VCC** (5 V), 4 **SCL**. This is not the Qwiic / STEMMA QT order, on purpose: those boards are 3.3 V.

The sensor board's socket has the same signals turned end for end (1 SCL, 2 VCC, 3 GND, 4 SDA), so a **1:N** JST SR jumper (A04SR04SR30K152B) connects them pin for pin. Don't use a 1:1 jumper: it puts 5 V on the sensor's ground. To lengthen a lead, cut the jumper and splice a 4-wire cable in between, wire for wire.

## Setting the start and stop

On the **Board** page, with the board connected, each AX row says its sensor's state, and on the right is the **AS5600 sensors (I²C)** helper.

1. Assemble the mechanism with the sensor in place and plug the board into USB.
2. In the helper, pick the port. **State** should say **OK**, the **AGC** should be somewhere in the middle (it sits at an end when the magnet is too close or too far), and the **Raw angle** should follow the control.
3. Move the control to the end where the reading should start, and click **Set start**.
4. Move it to the other end, at least 18° away, and click **Set stop**. The helper follows the raw angle in between, so it knows which way you went and how far. The board saves the range at once, writes it to the sensor, and the state adds **range set on the sensor**.
5. The **Output** bar now runs from 0 at the start to 4095 at the stop. That's what the axis gets.
   - If the angle falls from your start to your stop (the sensor turns counterclockwise), the helper sets the range the other way round and says so: the output then runs from 4095 at your start to 0 at your stop. Tick **Inverted** on the axes using that port.
6. Click **Use the sensor's whole output as the calibration** to set the calibration of every axis that uses that port to the full range (choose the port as an axis source on the Axes Config page first). Then **Write config to Device**.

**Whole circle** clears the range: the sensor reads 0–4095 over a full turn again. For a 360° control, set the wrap point with the axis's **Offset** instead.

The start and stop belong to the board, not to a profile: writing a profile, resetting the settings or updating the firmware leaves them alone. The helper saves them as soon as you click; there's no need to write the config for them.

## The I²C clock

**100 kHz** is the default and suits most cables. If a port with a long cable shows errors, choose **50 kHz** or **25 kHz** in the helper (10 kHz is there as a last resort). The board saves it at once. The firmware reads one port per pass, so a slower clock makes each pass longer: by about 1.7 ms at 100 kHz, 7 ms at 25 kHz and 17 ms at 10 kHz (calculated from the transfers, not measured). At 10 kHz the buttons and the USB reports slow down to match.

## Examples from the UH-1 collective

- **Collective, in the MkIII base, on AX1:** set start with the collective fully **down**, set stop fully **up**. The angle falls as the lever lifts, so the helper sets the range the other way round: tick **Inverted** on the collective's axis.
- **Throttle, in the Huey head, on AX4:** set start at the **idle** stop, set stop at **full open**. The angle rises; nothing to invert.

## Troubleshooting

| The state says | Why, and what to do |
|---|---|
| no sensor | Nothing answers on that port: check the cable is a 1:N jumper and is plugged in at both ends. A sensor plugged in later gets its range as soon as it answers |
| no magnet / magnet too weak or too far | Move the magnet closer and centre it over the chip |
| magnet too strong or too close | Move it further away |
| the board's I²C switch doesn't answer | Every port says so: the PCA9546A or its pull-ups (R9–R11) aren't working. On a bare Pro Micro with HeliSR firmware this is normal |
| bus stuck: check this port's cable | Something on that port held a line low. The firmware resets the switch, leaves the port alone for a moment and carries on with the others. Check the cable for a short, and try a slower clock |
| errors keep counting on a long cable | Try a slower I²C clock, and check the lead's splices |
| range not set on the sensor yet | The board couldn't write the start and stop, or the chip didn't keep them; it tries again every few visits |

A chip whose range was burnt in before (through its OUT pin, or over I²C elsewhere) may still work on the sensor board: the board writes its own start and stop over the burnt ones every time it starts. Whether a burnt chip keeps them hasn't been tried; if it doesn't, its state says "range not set on the sensor yet".
