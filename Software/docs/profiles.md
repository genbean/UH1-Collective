# Profiles

A profile is a whole HeliSR setup in one file (`.cfg`): every page's settings, including the device's name. Use them to keep a setup, try another one, put a board back as it was, or share a setup with someone who built the same thing.

- **Save config to file** saves what's on the pages. Read the board's settings first (**Read config from Device**) if you want those.
- **Load config from file** puts a profile on the pages. Nothing goes to the board until **Write config to Device**.
- Profiles in `Documents\HeliSR\configs` also appear in the list above those buttons; picking one loads it.

The app comes with three examples, which it copies to **`Documents\HeliSR\configs\examples`**: Load config from file opens in `configs`, so the `examples` folder is right there. The same files are in [`Software/profiles`](../profiles).

Profiles hold HeliSR settings only: profiles from FreeJoy or MMJoy2 can't be loaded.

## Default (16 buttons, 4 axes)

The factory settings: IN1–IN16 are buttons 1–16, AX1–AX4 are the X, Y, Z and Rx axes, and the device is called HeliSR. Load it and write it to start a board afresh.

## UH-1 collective (HeliSR head)

For the UH-1 collective built from this project: the Huey head ([`Head`](../../Head/README.md#controls)) on a HeliSR Rev 3.0 board, the collective's AS5600 in the MkIII base on AX1, and the throttle's AS5600 on AX4. The device is called **UH-1 Collective**.

**Axes:**

| Axis | Input | |
|---|---|---|
| Z | AX1 | Collective |
| Rz | AX4 | Throttle: 0 at cutoff, about 8 % at the idle gate, full at full open |

Filter level 1 on both. X, Y and Rx are off, so the spare AX2 and AX3 can't add stray axes. Program both AS5600s first (see the [AS5600 guide](as5600.md)), then calibrate each axis, or use the AS5600 helper's measured range.

**Buttons** (game button numbers):

| Button | Input | Control |
|---|---|---|
| 1 | IN1 | GOV RPM INCR |
| 2 | IN2 | GOV RPM DECR |
| 3 | IN3 | LDG LT EXT |
| 4 | IN4 | LDG LT RETR |
| 5 | IN3 + IN4 off | LDG LT EXT / RETR switch in the middle (Switch center) |
| 6 | IN5 | SL ON |
| 7 | IN6 | SL STOW |
| 8 | IN5 + IN6 off | SL switch in the middle, OFF (Switch center) |
| 9 | IN7 | LDG LT ON |
| 10 | IN7, inverted | LDG LT OFF |
| 11 | IN9 | SEARCH CONT EXT |
| 12 | IN10 | SEARCH CONT RETR |
| 13 | IN11 | SEARCH CONT L |
| 14 | IN12 | SEARCH CONT R |
| 15 | IN13 | STOP REL (the idle release) |
| 16 | IN14 | Starter trigger |
| 17 | Rz range 1 | Throttle in the cutoff range (the bottom 7 % of the throttle) |

Each switch position has its own button, so every position can be bound in a sim, middle positions included. The search light hat is wired as four buttons (IN9–IN12 in the order EXT, RETR, L, R); swap the inputs in the Physical column if yours differ. IN8, IN15, IN16, AX2 and AX3 are spare.

## Button box (switches, encoders, hat)

A generic panel that shows the button types; adapt it to your own. No axes. The device is called **HeliSR Button Box**.

| Logical button | Game button | Input | What it shows |
|---|---|---|---|
| 1, 2, 3 | 1, 2, 3 | IN1, IN2, both off | An ON-OFF-ON switch: up, down, and the centre (Switch center) |
| 4, 5, 6 | 4, 5, 6 | IN3, IN4, both off | Another ON-OFF-ON switch |
| 7 | 7 | IN5 | Toggle switch ON: a short press when switch C turns on |
| 8 | 8 | IN5 | Toggle switch OFF: a short press when it turns off |
| 9 | 9 | IN6 | Button toggle: a push button that latches on and off |
| 10, 11 | 10, 11 | IN7, IN8 | Encoder 1 (Encoder A, Encoder B), 1x: one press per click |
| 12, 13 | 12, 13 | IN9, IN10 | Encoder 2 |
| 14–17 | the hat | IN11–IN14 | Hat 1: up, right, down, left. Hat directions don't take button numbers |
| 18 | 14 | IN15 | Shift 1 |
| 19 | 15 | IN16 | Works while no shift is held |
| 20 | 16 | IN16, shift 1 | IN16 with IN15 held |

## Making your own

Start from the example closest to what you built, change it on the pages, and **Save config to file** under a new name. The [user guide](user-guide.md) explains every setting.

The examples are generated by [`Software/profiles/make_profiles.py`](../profiles/make_profiles.py) from the factory-settings profile, so they stay in step with the firmware's defaults.
